Mapa de componentes e glossário do Claude

Tudo o que aparece na trilha preliminar, num lugar só: as peças que compõem um ambiente produtivo com o Claude, quando vale adicionar cada uma, os arquivos onde ficam e o significado de cada termo. Volte aqui sempre que uma palavra nova aparecer.

Fonte e dataBaseado na documentação oficial do Claude Code e na versão 2.1.316, em novembro de 2026. O produto muda toda semana: na dúvida, a documentação oficial em português vale mais do que esta página. Para conceitos de modelo (tokens, temperatura, RAG), veja também o glossário da plataforma.

O que adicionar, e quando

Não configure tudo no primeiro dia. A documentação oficial recomenda adicionar cada peça quando aparecer o sinal certo:

SinalO que adicionar
O Claude errou uma convenção ou um comando duas vezesEscreva no CLAUDE.md
Você sempre pede o mesmo formato de respostaDefina um estilo de saída
Você digita o mesmo pedido para começar uma tarefaCrie uma skill que você chama com /nome
Você cola o mesmo procedimento pela terceira vezTransforme em skill
Você copia dados de um sistema que o Claude não vêConecte esse sistema por MCP
O Claude lê muitos arquivos para achar um símboloInstale o plugin de inteligência de código da linguagem
Uma tarefa lateral enche a conversa de saídaMande para um subagente
Algo precisa acontecer sempre, sem pedirEscreva um hook
Os pedidos de permissão estão atrapalhandoRode /fewer-permission-prompts, ligue o sandbox ou use o modo auto (Módulo P4)
Um segundo repositório precisa do mesmo ambienteEmpacote como plugin

Eventos de hook

Os principais pontos do ciclo de vida em que um hook pode rodar. A lista completa está na referência de hooks.

EventoQuando e para quê
SessionStart / SessionEndInício e fim da sessão: preparar ambiente, registrar
UserPromptSubmitAntes de o Claude ler seu pedido: adicionar contexto, bloquear
PreToolUseAntes de uma ferramenta rodar: pode bloquear (a barreira mais usada)
PermissionRequest / PermissionDeniedQuando uma ação pede permissão ou é negada pelo modo auto
PostToolUse / PostToolUseFailureDepois de uma ferramenta: formatar, rodar lint, registrar
Stop / StopFailureQuando o Claude termina ou falha por erro de API: checar se testes passam
SubagentStart / SubagentStopInício e fim de subagentes
PreCompact / PostCompactAntes e depois da compactação
NotificationQuando o Claude Code notifica (por exemplo, esperando permissão)
ConfigChange, FileChanged, CwdChanged, InstructionsLoadedMudanças de configuração, arquivos, pasta e instruções
WorktreeCreate / WorktreeRemove, TaskCreated / TaskCompletedWorktrees e tarefas

Glossário A–Z

A

acceptEdits
Modo de permissão que aprova edições de arquivos e comandos simples de arquivo (mkdir, mv, cp) sem perguntar. Módulo P4. documentação
Agent SDK (Claude Agent SDK)
Biblioteca em TypeScript e Python que dá aos seus programas o mesmo motor do Claude Code: ciclo agêntico, ferramentas, permissões, hooks e sessões. Módulo P8. documentação
Agente (agent)
Sistema em que o modelo decide quais ferramentas usar e em que ordem, observando o resultado de cada passo até concluir a tarefa. O Claude Code é um agente de código. Módulo P1. documentação
AGENTS.md
Arquivo de instruções para agentes de código, padrão aberto. Se o repositório tem AGENTS.md e não tem CLAUDE.md, o Claude Code o lê como instruções do projeto. Módulo P3. documentação
Artefato (artifact)
Página web privada e interativa que o Claude publica no claude.ai a partir da sessão, para você ver ou compartilhar um resultado visual em vez de ler texto no terminal. Módulo P2. documentação
autoMode.environment
Configuração que diz ao classificador do modo auto quais repositórios, domínios, buckets e serviços são confiáveis. Lida do settings do usuário ou da organização, nunca do repositório. Módulo P4. documentação
Autonomia (escada da)
Termo do curso para a sequência de modos de permissão, do mais supervisionado ao mais livre: manual, acceptEdits, plano, auto, dontAsk e bypassPermissions. Subir na escada exige barreiras proporcionais. Módulo P4. documentação

B

Bare (modo) (bare mode)
Flag --bare: inicia sem carregar hooks, skills, plugins, servidores MCP, memória automática nem CLAUDE.md. Recomendado em CI, para o resultado ser igual em qualquer máquina. Módulo P7. documentação
bypassPermissions
Modo de permissão que pula todas as checagens (flag --dangerously-skip-permissions). Só para contêineres e máquinas virtuais isolados, como usuário sem privilégios de root. Regras deny continuam valendo. Módulo P4. documentação

C

Canal (channel)
Servidor MCP que empurra eventos (mensagens, alertas, webhooks) para uma sessão em andamento, para o Claude reagir enquanto você está longe do terminal. Módulo P6. documentação
Checkpoint
Ponto de restauração criado a cada mensagem sua. Esc duas vezes ou /rewind volta o código, a conversa ou ambos. Não desfaz o que um comando de terminal mudou fora das ferramentas de edição. Módulo P2. documentação
Ciclo agêntico (agentic loop)
O ciclo que o Claude repete em toda tarefa: coletar contexto, agir, verificar o resultado e repetir até terminar. Você pode interromper a qualquer momento. Módulo P2. documentação
Classificador do modo auto
Modelo separado que revisa cada ação no modo auto e bloqueia o que for irreversível, destrutivo, fora do escopo ou induzido por prompt injection. Não vê o resultado das ferramentas, para não ser manipulado por ele. Módulo P4. documentação
claude -p (print / non-interactive mode)
Modo não interativo: executa um único pedido e sai. Base para scripts, CI e pipelines. Aceita --output-format json, --json-schema, --max-turns e --max-budget-usd. Módulo P7. documentação
CLAUDE.md
Arquivo de instruções permanentes que você escreve para o Claude: convenções, comandos de teste, regras do tipo "sempre faça X". Carregado no início de toda sessão e relido do disco após a compactação. Módulo P3. documentação
Code Review
Serviço que revisa automaticamente cada pull request no GitHub com vários agentes. No terminal, o equivalente local é /code-review; ultrareview faz uma revisão mais profunda na nuvem. Módulo P7. documentação
Comando de barra (slash command)
Instrução reutilizável chamada com /nome, como /clear, /model e /compact. Comandos próprios hoje são feitos como skills. Módulo P2. documentação
Compactação (compaction)
Resumo automático da conversa quando a janela de contexto enche. O CLAUDE.md da raiz e a memória automática sobrevivem; instruções dadas só na conversa podem se perder. /compact força a compactação. Módulo P2. documentação
Conector (connector)
Servidor MCP adicionado à sua conta do claude.ai (Gmail, Drive, Slack…). Aparece no /mcp do Claude Code quando você entra com a mesma conta. Módulo P5. documentação
Contexto (janela de) (context window)
A memória de trabalho da sessão: conversa, arquivos lidos, saídas de comandos, CLAUDE.md, skills e instruções do sistema. /context mostra o que ocupa espaço. Módulo P1. documentação

D

Dev container
Contêiner de desenvolvimento configurado no repositório. Dá isolamento consistente para rodar o Claude com mais autonomia sem expor sua máquina. Módulo P4. documentação
Dispatch
Envio de uma tarefa pelo app do celular que abre uma sessão do Claude Code no app desktop. Módulo P6. documentação
dontAsk
Modo de permissão em que só rodam leituras e ferramentas pré-aprovadas; o que pediria permissão é negado. Ideal para CI com lista exata do que pode. Módulo P7. documentação

E

Equipe de agentes (agent teams)
Várias sessões do Claude Code coordenadas por uma líder, com lista de tarefas compartilhada e mensagens entre elas. Experimental, desligada por padrão. Módulo P6. documentação
Esforço (nível de) (effort level)
Quanto o modelo raciocina em cada passo: low, medium, high, xhigh ou max. Mais esforço, respostas mais cuidadosas, mais lentas e mais caras. /effort ou --effort. Módulo P2. documentação
Estilo de saída (output style)
Configuração que muda o papel, o tom e o formato das respostas em toda a sessão, inclusive para usar o Claude em tarefas que não são de programação. Módulo P3. documentação

F

Ferramenta (tool)
Uma ação que o Claude pode executar: ler arquivo, editar, rodar comando, buscar na web, criar subagente. É o que transforma o modelo em agente. Módulo P2. documentação
Fluxo dinâmico (dynamic workflow)
Script que o Claude escreve para orquestrar muitos subagentes em segundo plano, por exemplo para auditar um código inteiro com verificação cruzada. Módulo P6. documentação
Frontmatter
Bloco YAML entre linhas --- no topo de um arquivo Markdown. Skills, subagentes, estilos de saída e regras leem sua configuração dali. Módulo P5. documentação

G

GitHub Actions (Claude Code)
Integração que roda o Claude Code em workflows do GitHub: responder a menções em issues e PRs, corrigir CI, revisar código. /install-github-app configura. Módulo P7. documentação
/goal
Define uma condição de conclusão; o Claude continua trabalhando até que ela seja verdadeira. Módulo P6. documentação

H

Harness (agentic harness)
As ferramentas, o gerenciamento de contexto e o ambiente de execução que transformam um modelo em agente. O Claude Code é o harness; o Claude é o modelo dentro dele. Módulo P1. documentação
Hook
Ação que roda automaticamente em um ponto do ciclo de vida (antes de uma ferramenta, depois de uma edição, no início da sessão). Pode ser comando, HTTP, ferramenta MCP, prompt ou subagente. Determinístico: não depende da vontade do modelo. Módulo P5. documentação

I

Injeção de prompt (prompt injection)
Instruções hostis escondidas em arquivos, páginas ou resultados de ferramentas, que tentam desviar o agente. A principal razão para não dar autonomia sem barreiras. Módulo P4. documentação
Inteligência de código (code intelligence / LSP)
Plugin que conecta o Claude a um servidor de linguagem, para navegar por símbolos e ver erros de tipo sem ler arquivos inteiros. Módulo P5. documentação

L

/loop
Skill que repete um pedido em intervalos durante a sessão, por exemplo para acompanhar um deploy ou um PR. Módulo P6. documentação

M

Managed settings (configurações gerenciadas)
Configurações impostas pela organização, que usuários e projetos não podem sobrescrever. Usadas para regras de segurança de toda a empresa. Módulo P8. documentação
Marketplace
Catálogo de plugins, definido por um marketplace.json, de onde se instalam plugins com /plugin ou claude plugin install. Módulo P5. documentação
MCP (Model Context Protocol)
Padrão aberto para conectar a IA a ferramentas e dados externos: bancos, Slack, Jira, navegador e centenas de outros. Visto em profundidade no Módulo 5 do curso principal. Módulo P5. documentação
MCP Tool Search
Mecanismo que carrega só os nomes das ferramentas MCP no início e busca o esquema completo quando for usar, para muitos servidores não lotarem o contexto. Módulo P5. documentação
.mcp.json
Arquivo do projeto com os servidores MCP compartilhados pelo time. Cada pessoa aprova os servidores antes de eles conectarem. Módulo P5. documentação
Memória automática (auto memory)
Notas que o Claude escreve para si mesmo a partir das suas correções e preferências, guardadas por repositório. Contraparte do CLAUDE.md, que é você quem escreve. Módulo P3. documentação
Mod
Plugin que altera a própria interface e o comportamento do Claude Code: painéis, faixas, comandos e regras sobre chamadas de ferramentas. Módulo P5. documentação
Modelo de linguagem (LLM)
Programa treinado em muito texto para prever a continuação mais provável. Com ferramentas, passa a agir; sem verificação, pode errar com confiança. Módulo P1.
Modo auto (auto mode)
Modo de permissão em que o classificador revisa as ações no seu lugar, e o Claude roda a maioria sem perguntar. É o modo inicial padrão nas versões atuais do terminal e do VS Code. Módulo P4. documentação
Modo manual (default)
Modo de permissão que pede aprovação para tudo que não é leitura. Valor de configuração: default. Módulo P4. documentação
Modo plano (plan mode)
Modo em que o Claude pesquisa e propõe um plano sem editar seus arquivos. /plan ou Shift+Tab. Módulo P2. documentação

P

Plugin
Pacote instalável com skills, hooks, subagentes e servidores MCP. Suas skills ganham prefixo (plugin:skill) para coexistir. Módulo P5. documentação
Projeto (confiança no) (project trust)
Diálogo em que você aceita uma pasta antes de o Claude Code carregar a configuração dela. Até lá, regras allow e marketplaces do repositório ficam retidos. Módulo P4. documentação

R

Regra de permissão (permission rule)
Entrada allow, ask ou deny no settings.json, como Bash(npm test) ou Read(./.env). Avaliadas na ordem deny, ask, allow; vale a primeira que bater. Deny vale em todos os modos. Módulo P4. documentação
Regras (rules)
Arquivos em .claude/rules/ carregados junto com o CLAUDE.md. Podem valer só para certos caminhos (frontmatter paths:), economizando contexto. Módulo P3. documentação
Remoção crítica (critical-path removal)
rm ou rmdir em caminhos críticos (raiz, home, pastas do sistema). Nenhum modo aprova sozinho, nem bypassPermissions por padrão. Módulo P4. documentação
Remote Control
Continuar uma sessão local pelo celular ou navegador. O código continua rodando na sua máquina; só a interface é remota. Módulo P6. documentação
Rotina / tarefa agendada (scheduled task)
Pedido que roda sozinho em horário definido, na nuvem (/schedule) ou no app desktop. Antes chamado de routine. Módulo P7. documentação

S

Sandbox (sandboxing)
Isolamento de arquivos e rede no nível do sistema operacional para os comandos de terminal. Dentro do limite definido, o Claude trabalha sem pedir permissão a cada comando. /sandbox liga. Módulo P4. documentação
Sessão (session)
Uma conversa ligada a uma pasta, com contexto próprio. claude -c continua a última; /resume escolhe; /clear começa outra. Módulo P2. documentação
Sessão em segundo plano (background session)
Sessão que roda sem ocupar o terminal: claude --bg ou /background. claude agents lista, attach abre, stop para. Módulo P6. documentação
Sessão na nuvem (cloud session)
Sessão que roda na infraestrutura da Anthropic (ou da sua empresa) e continua com o notebook fechado. Começa de um clone novo do repositório. Módulo P6. documentação
settings.json (camadas) (settings layers)
Configuração em camadas, da mais forte para a mais fraca: gerenciada, flag --settings, .claude/settings.local.json, .claude/settings.json e ~/.claude/settings.json. Listas se somam; valores simples da camada mais forte vencem. Módulo P3. documentação
Skill
Arquivo SKILL.md com instruções, conhecimento ou um procedimento. O Claude carrega quando é relevante, ou você chama com /nome. Segue o padrão aberto Agent Skills. Módulo P5. documentação
Skills embutidas (bundled skills)
Skills que já vêm no Claude Code, como /batch, /code-review, /debug, /loop, /run, /simplify e /fewer-permission-prompts. Módulo P5. documentação
Subagente (subagent)
Assistente especializado com contexto, prompt, ferramentas e permissões próprios. Faz uma tarefa delegada e devolve um resumo. Embutidos: Explore, Plan e general-purpose. Módulo P5. documentação
Superfície (surface)
Onde você usa o Claude Code: terminal, VS Code, JetBrains, app desktop, claude.ai, celular. Todas usam o mesmo motor. Módulo P1. documentação
System prompt
Instruções que o Claude Code envia antes da conversa em todo pedido. Pode ser complementado com --append-system-prompt. Módulo P3. documentação
System reminder
Mensagem que o harness insere na conversa para dar contexto: seu CLAUDE.md, a lista de skills, o texto de um hook, o aviso de que um arquivo mudou. Módulo P3. documentação

T

Teleport
/teleport traz uma sessão da nuvem para o seu terminal, com a branch e a conversa. O caminho inverso é --cloud. Módulo P6. documentação
Token
Pedaço de texto (em média, parte de uma palavra) que o modelo lê e escreve. Contexto, limites e preço são medidos em tokens. Módulo P1.
Transcrição (transcript)
Registro guardado de uma sessão: mensagens, chamadas de ferramentas e resultados. Permite retomar e auditar o que o agente fez. Módulo P2. documentação
Turno (turn)
Uma rodada: sua mensagem e tudo que o Claude faz até devolver a vez. Módulo P2. documentação

V

Verificação (ciclo de) (verification loop)
Dar ao Claude um jeito de conferir o próprio trabalho (testes, build, captura de tela) para ele corrigir sozinho até passar. A prática que mais aumenta a qualidade com autonomia. Módulo P2. documentação

W

Worktree
Cópia de trabalho separada do mesmo repositório git. Permite várias sessões em paralelo sem uma sobrescrever a outra. claude -w cria uma. Módulo P6. documentação
