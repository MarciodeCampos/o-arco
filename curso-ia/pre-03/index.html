Trilha com agentes · Módulo P3 · 10h estimadas

Desenvolver com agentes

Na trilha com agentes você não escreve código: o Claude escreve. O seu trabalho é outro, e não é menor. Você diz aonde quer chegar e como saber que chegou, decide sobre cada proposta importante, confere o resultado e registra por que decidiu. Este módulo ensina essas quatro coisas. Com elas, você faz os laboratórios do curso resolvendo os mesmos problemas que a trilha com código.

7 aulaspré-requisito: P1 e P2sem programação
Antes de começar Você precisa do Claude Code instalado e configurado. O plugin autonomo faz isso com você, e o P2 explica o que ele está fazendo.

P3.1 O ciclo de trabalho: objetivo, proposta, autorização, conferência

Leitura · 1h

Todo trabalho nesta trilha segue o mesmo ciclo:

  1. Objetivo: você diz o que quer e como vai saber que está pronto (P3.2).
  2. Proposta: o Claude estuda o problema e propõe o próximo passo, explicando por quê.
  3. Autorização: você autoriza, pede outro caminho ou pede uma segunda opinião (P3.3 e P3.6).
  4. Conferência: o Claude executa e mostra a evidência de que funcionou; você confere (P3.4).

O ciclo se repete até o critério de pronto ser atingido. Nem todo passo precisa da sua autorização. O que decide é o risco, não o tamanho da tarefa:

O Claude…Exemplos
Sempre pede autorizaçãoPublicar na internet, gastar dinheiro, apagar dados, enviar algo para fora (e-mail, outra empresa, outro provedor de IA), mudar as próprias permissões
Pede conforme o nível de autonomia que você escolheu no pluginInstalar programas, criar repositórios, mudar a estrutura do projeto
Faz e conta depoisEditar arquivos do projeto, rodar testes, criar uma branch. Tudo isso se desfaz

Quiz rápido

O Claude quer publicar a primeira versão do seu site. O que deve acontecer?

Publicar não se desfaz por completo: alguém pode ter visto. Por isso sempre passa por você, com prévia.

P3.2 Dizer aonde quer chegar e o que é "pronto"

Leitura + prática · 1h30

Um agente trabalha bem sozinho quando sabe conferir o próprio trabalho. Para isso, o pedido precisa de um critério de pronto verificável: algo que um teste, uma conta ou uma pessoa consiga dizer se está certo ou não. Use este modelo: 

Quero: [o resultado, com um verbo]
Para: [quem vai usar e para quê]
Pronto quando:
  1. [algo que dá para conferir]
  2. [outro]
Não pode: [o que não deve mudar ou acontecer]
Antes de cada etapa importante, me mostre o que propõe, por quê, as alternativas e o risco.
Critério vagoCritério verificável
"Que funcione bem.""Os 4 recibos de exemplo saem com o total igual à soma dos itens."
"Que seja rápido.""Responde em menos de 3 segundos em 9 de cada 10 pedidos."
"Que não gaste muito.""Custa menos de R$ 0,05 por recibo, e você me mostra a conta."

O plugin autonomo transforma esses critérios em testes automáticos. Quando todos passam, o trabalho está pronto; quando um falha, o Claude sabe o que corrigir sem precisar perguntar a você.

P3.3 Decidir sobre as propostas do Claude

Leitura + prática · 1h30

Cada decisão importante chega num formato fixo, o cartão de decisão. Se o Claude esquecer algum campo, peça.

O que proponho
Guardar os cadastros numa planilha do Google em vez de um banco de dados.
Por quê
São menos de 500 linhas, você já usa o Drive e consegue conferir os dados sem mim.
Alternativas
Um banco de dados gratuito: mais trabalho agora, aguenta crescer.
Risco e como desfazer
Baixo. Migrar depois leva cerca de uma hora.
O que preciso de você
Autorizar, escolher a alternativa ou pedir uma segunda opinião.

Quatro perguntas para não autorizar no automático:

  1. Eu entendi o porquê? Se não, peça: "explique como se eu nunca tivesse programado".
  2. Dá para desfazer? Se não dá, leia com mais calma e peça uma prévia.
  3. Isso aproxima do critério de pronto? Se o passo não tem relação com o objetivo, pergunte por que ele é necessário.
  4. O que eu perco com a alternativa? Toda escolha tem um custo; saber qual é faz parte da decisão.

Registre cada decisão importante num arquivo DECISOES.md no projeto. Peça ao Claude para criar e manter, mas o motivo da decisão é seu:

## 2026-11-02 · Onde guardar os cadastros
Proposta: planilha do Google (alternativa: banco de dados gratuito)
Segunda opinião: não pedi
Decidi: planilha
Por quê: são poucos dados e eu preciso conferir sem depender de ninguém.
Rever quando: passar de 2 mil cadastros

P3.4 Conferir o resultado sem ler código

Leitura + prática · 1h30

Você não precisa ler o código para saber se ele funciona. Precisa ler a evidência:

EvidênciaComo lerO que pedir ao Claude
Resultado dos testespass ou ✓ é aprovado; fail ou ✗ é reprovado. Olhe o total no fim: "14 pass, 0 fail""Rode os testes e me mostre o resultado, um por linha, com o que cada um confere"
A saída com os seus exemplosCompare com o que você esperava, caso a caso"Rode com os 4 recibos e me mostre uma tabela: esperado, obtido, certo ou errado"
A préviaAbra o endereço e use como um usuário usaria"Publique uma prévia e me dê o link"
O resumo da mudança (diff)Verde é o que entrou, vermelho o que saiu"Explique em linguagem simples o que mudou e por quê, arquivo por arquivo"
Desconfie de teste que nunca falha Um teste que só confere "o programa rodou" passa mesmo com o resultado errado. Peça ao Claude para mostrar um teste falhando de propósito (com um valor errado) e depois passando. Se ele não consegue fazer o teste falhar, o teste não confere nada.

P3.5 Quando travar

Leitura · 30min
  • Erro que você não entende: "Explique este erro em linguagem simples e proponha duas saídas, com o risco de cada uma."
  • O Claude anda em círculos (tenta a mesma correção várias vezes): peça para ele parar, resumir o que tentou e o que aprendeu, e propor uma abordagem diferente.
  • Algo que funcionava quebrou: "Volte para a última versão em que os testes passavam e me mostre o que mudou desde então." O Git guarda todas as versões.
  • Você não sabe se a proposta é boa: peça uma segunda opinião (P3.6).

P3.6 Segunda opinião: Gemini e GPT na decisão

Leitura + prática · 1h

Antes de uma decisão importante, você pode ouvir outros modelos. O jeito mais simples não custa nada a mais: peça ao Claude a pergunta pronta, cole no ChatGPT ou no Gemini que você já usa e traga a resposta de volta. 

Prepare uma pergunta para eu levar ao GPT e ao Gemini sobre esta decisão.
Inclua só o contexto necessário, sem dados pessoais, senhas ou documentos sigilosos.
Depois que eu colar as respostas, me diga onde vocês concordam, onde divergem
e o que você recomenda agora, avisando se mudou de ideia.
  • Opinião informa, teste decide. Três modelos podem concordar e estar errados, porque aprenderam de textos parecidos. Perguntas de fato (funciona? a conta está certa?) se resolvem com teste, não com votação.
  • Vale para decisões de julgamento: escolher entre duas soluções, revisar um texto para cliente, avaliar um risco.
  • Privacidade: mandar contexto para outro modelo é enviar dados para outra empresa. Confira o que vai na pergunta antes de colar.
  • Registre as opiniões e a sua decisão no DECISOES.md.

P3.7 Como funcionam os laboratórios com agentes

Leitura · 30min

Os laboratórios das duas trilhas têm o mesmo problema, o mesmo objetivo e o mesmo critério de pronto. Na trilha com agentes, você aprende como o problema se resolve vendo o Claude resolver, e depois resolve uma variação conduzindo o Claude. Saber como se resolve vale tanto quanto ter resolvido. Só assistir dá a sensação de ter entendido sem ter entendido; por isso cada laboratório tem cinco momentos:

MomentoO que você faz
1. O problemaEscreve como acha que resolveria, antes de ver
2. A resolução comentadaAcompanha o Claude resolvendo e, nos pontos marcados, prevê o próximo passo
3. Por quêExplica com as suas palavras por que um passo foi necessário
4. Ache o erroEncontra o erro numa resolução parecida e diz como percebeu
5. VariaçãoConduz o Claude até resolver o problema com uma mudança, só com pedidos e autorizações

Nas páginas dos módulos, o seletor Sua trilha mostra a versão de cada laboratório. A versão da outra trilha fica recolhida, como opcional: abrir para ver como um desenvolvedor resolve o mesmo problema ajuda a entender o que o Claude fez.

Projeto do módulo: o primeiro laboratório com agentes

Projeto · 1h30 (mais o laboratório)

Faça o projeto do Módulo 2, o extrator de recibos, na versão com agentes. É o mesmo problema que a trilha com código resolve escrevendo o programa. Este módulo está concluído quando você tem:

  1. O pedido inicial com critério de pronto verificável (P3.2).
  2. Um DECISOES.md com pelo menos cinco decisões, cada uma com o seu porquê (P3.3).
  3. Os testes passando, e um teste que você viu falhar de propósito (P3.4).
  4. Uma decisão tomada com segunda opinião (P3.6).
