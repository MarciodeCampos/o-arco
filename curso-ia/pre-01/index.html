Introdução · Módulo P1 · 8h estimadas

IA sem mistério e o ecossistema Claude

Para quem nunca trabalhou com IA. Antes de dar autonomia a um agente, é preciso entender o que ele é: um programa muito bom em linguagem, que erra com confiança quando não tem como verificar o que fez. Este módulo explica isso sem matemática, apresenta os modelos e os lugares onde o Claude roda, e ensina a pedir de um jeito que dá para conferir.

P1.1 O que é um modelo de linguagem, sem matemática

Leitura · 1h30

Um modelo de linguagem é um programa que aprendeu, lendo uma quantidade enorme de texto, a prever qual pedaço de texto vem a seguir. Repetindo essa previsão milhares de vezes, ele escreve respostas, resume documentos, traduz e escreve código. O Módulo 1 do curso principal mostra isso por dentro; aqui basta guardar quatro ideias:

  • Ele não consulta um banco de fatos. Gera o texto mais plausível. Na maioria das vezes plausível é correto; às vezes é uma invenção bem escrita, a chamada alucinação.
  • Ele não lembra de você entre conversas, a menos que alguém guarde e devolva essa informação, como o CLAUDE.md que o plugin autonomo configura.
  • Com ferramentas, ele age. Se pode ler arquivos, rodar comandos e ver o resultado, deixa de só falar e passa a fazer. Isso é um agente, e o Claude Code é um.
  • Com um jeito de conferir, ele se corrige. Um agente que roda os testes depois de mudar o código vê o erro e conserta. Esse ciclo de verificação é a base de toda autonomia segura.

Quiz rápido

Por que um agente com testes automáticos é mais confiável do que um chat que só escreve código?

O modelo continua podendo errar. A diferença é que o agente tem como perceber o erro e corrigir sozinho.

O que é uma alucinação?

Por isso fatos importantes devem ser conferidos, ou o modelo deve trabalhar com fontes que ele cita.

O plugin autonomo usa principalmente o Claude Code, porque é nele que estão a autonomia, os testes e as implantações. Todas as superfícies usam o mesmo motor: o que você aprende no terminal vale no editor e na nuvem.

Quiz rápido

Você quer que o Claude continue uma tarefa longa com o notebook fechado. Qual superfície?

Sessões na nuvem rodam na infraestrutura da Anthropic. Uma sessão local para quando a máquina dorme; Remote Control só deixa você acompanhá-la de outro aparelho.

P1.4 Contexto, tokens, limites e custos

Leitura + prática · 1h30
  • Token é o pedaço de texto que o modelo lê e escreve, em média menor que uma palavra. Preço, limites e memória de trabalho são medidos em tokens.
  • Janela de contexto é tudo que o modelo enxerga de uma vez: a conversa, os arquivos lidos, as saídas de comandos e as instruções. Quando enche, o Claude Code resume a conversa (compactação). /context mostra o que está ocupando espaço.
  • Assinatura ou API: nos planos (Free, Pro, Max, Team, Enterprise) você paga um valor fixo e tem limites de uso; /usage mostra quanto já usou. Pela API, paga por token consumido.
  • Saída custa mais que entrada: cinco vezes mais, em todos os modelos da tabela acima. Pedir respostas mais curtas economiza.

P1.5 Privacidade, uso de dados e o que nunca colar

Leitura · 1h
Tipo de contaTreinamento de modelosRetenção padrão
Pessoal (Free, Pro, Max, Ultra)Só se você permitir, nas configurações de privacidade30 dias sem permissão; 5 anos com permissão
Comercial (Team, Enterprise, API)Não treina com seus prompts e código, salvo adesão explícita30 dias; retenção zero disponível para contas qualificadas

Além disso, o Claude Code guarda as transcrições das sessões no seu computador, em texto, por 30 dias por padrão, para permitir retomar conversas.

Nunca cole numa conversa

  • Senhas, chaves de API, tokens de acesso. Use variáveis de ambiente e cofres de segredos; o plugin autonomo bloqueia o Claude de ler esses arquivos.
  • Dados pessoais de clientes sem base legal e contrato adequado (Módulo 12 do curso principal).
  • Informação sigilosa de terceiros que você não tem autorização para compartilhar.
FontePolítica de uso de dados do Claude Code, consultada em novembro de 2026. Confira a versão atual antes de decidir algo sensível; no Claude Code, /privacy-settings mostra suas opções.

P1.6 Como pedir bem: tarefa, contexto e critério de pronto

Leitura + prática · 1h30

A maior parte dos resultados ruins vem de pedidos vagos. Um bom pedido tem quatro partes:

  1. Tarefa: o que fazer, com verbo. "Corrija", "compare", "escreva", "investigue".
  2. Contexto: para quem, por quê, onde estão os dados, o que já foi tentado.
  3. Critério de pronto: como você e o Claude vão saber que terminou. "Os testes passam", "a planilha soma igual ao extrato", "cabe numa página".
  4. Limites: o que não pode. "Não mude a API pública", "não envie nada sem me mostrar".
Pedido vagoPedido verificável
"Melhora o site.""A página inicial leva 6 segundos para carregar no celular. Descubra o que mais pesa, proponha 3 mudanças e implemente a de maior ganho. Pronto quando o Lighthouse mobile passar de 85. Não mude o visual."
"Arruma esse bug.""Ao salvar um pedido sem CEP, o sistema dá erro 500. Escreva primeiro um teste que reproduz o erro, depois corrija até o teste passar, sem quebrar os outros."

O critério de pronto é o que torna a autonomia possível: com ele, o Claude pode trabalhar sozinho até atingir a meta, e você confere uma coisa só no final. Com o plugin autonomo, o Claude transforma esse critério em testes automáticos em todo projeto novo; no Claude Code, /goal faz ele trabalhar até a condição ser verdadeira.

CampoExemplo
Tarefa (com verbo)Atualizar as dependências do projeto e corrigir o que quebrar
Contexto que o Claude precisaRepositório X, comando de teste npm test, Node 22
Critério de prontoTodos os testes passam e o build gera os arquivos sem aviso
O que pode dar erradoMudança de comportamento não coberta por testes; atualização que exige migração de dados
